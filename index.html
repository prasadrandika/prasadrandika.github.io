What breaks

Changing the model name isn't enough. These are real problems I found while migrating open-source projects to gpt-6-luna, OpenAI's recommended replacement for gpt-4o-mini.

Tool calls need reasoning_effort: "none"

gpt-6-luna is a reasoning model. OpenAI's model page says Chat Completions supports function calling only with reasoning_effort set to "none". Otherwise, tool calls need to move to the Responses API.

tiktoken crashes

tiktoken.encoding_for_model("gpt-6-luna") raises KeyError, in both tiktoken 0.7.0 and 0.14.0. Code that counts tokens breaks the moment you rename the model.

temperature has to go

OpenAI's migration guide says to omit temperature, top_p and top_logprobs when moving to its newest reasoning models. It's often hidden in a shared client that always sends it.

Try it yourself

luna-check is free and open source (MIT). Run it on your own project to see what will break. It needs Python 3.9 or newer and Git.
